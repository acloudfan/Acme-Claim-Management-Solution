## REST API
A working REST API layer

### Customers API
    - /customers  # for customer information
        - /{customer_id}
            - /policies
                - /vehicles
                    - vehicle[{VIN, model, make, year, color,}]
            - /claims
                - add First Notice of Loss (FNOL), history
                - /{claim_id}
                    - damage details
                    - is car drivable
                    - current status of the claim
                    - actions taken on the claim so far (e.g., Initial estimate -> human review -> paid)
                    - /images
                        - /{image_id} # name of the image file name
                            - upload an image file to a claim
                            - delete an image file already added to claim - when image is deleted, delete the damage_id associated with the image
                


### Claims API
    - /claims  # not for customers
        - /{claim_id}
            - {details of claim, current status, status change events}
            - Update the status of the claim
            - /estimate
                - /ai               # A damage level estimation generated by AI
                - /human            # Human can use this to override AI's estimate
            - /human/review         # A human either approves or rejects the estimate. In case of rejection, the claim requires human adjustment
            - /state                # Update the state of the claim
            - /damages
                - /{damage_id}

### Cost Estimation API
    - /cost
        - /estimate             # Calculate repair cost for a damage report
                                # Input: damage_report with part, severity, confidence
                                # Output: labor_hours, parts_cost, total_cost
                                # Used by AI agent during damage assessment

## Image upload
* Verify : Image can only be added when Claim is 'draft' state. An attempt to load image to a claim that is not in draft state will result in error
* Customer will add image to the claim using the /api/v1/customers/{customer_id}/claims/{claim_id}/images
* Image will be analyzed by YOLO
* Damage report will be added to the claim
* Image uploaded event will be added to the event table
* There is NO change in claim status

## Claim submission
* Claim will be created in draft state
* Claim can be submitted ONLY if there is atleast 1 image of the damage
* On 'Claim submit'
    1. Each of the image will be assessed for damage using the YOLO model
    2. An AI Agent will then be used for assessing the 
    3. The cost for each damage will be estimated using /api/1/cost/estimate API
    4. Claim record will be updated
    5. Claim status will be changed to "FNOL"
    6. An event will be registered

### Adjustor front-end for human review
The idea of this Portal is to provide the "human reviewer" capability to review the claim in "human review" state. 
* Human reviewer will have a workflow queue that will show all the claims that are assigned to them for review
* Here is the flow for portal:
- Human reviewer will login (hardcoded password)
    - Human reviewer will see a list of claims assigned to them for review
    - Human reviewer click on a claim to open the details of the claim
    - Human reviewer will see all of the information about the claim (Vehicle details, Damage picture with annotations, cost estimates etc)
    - Human reviewer after the review will have the following choices:
        1. Do not make any change to the estimate and send it back for customer's approval
            - Human reviewer provides a customer_note that tells why appeal was rejected
            - Human reviewer provides a internal_note that tells why appeal was rejected - this will not be shown to customer
        2. Make changes to the claim estimates such as:
            1. Add new damages that AI missed out (HUMAN_ADDED_NEW_DAMAGE)
            2. Adjust the estimates for labor_rate - this is applied to all damages (HUMAN_ADJUSTED_LABOR_RATE)
            3. Adjust the estimates for labor_duration (HUMAN_ADJUSTED_LABOR_DURATION)
            4. Adjust the estimates for parts (HUMAN_ADJUSTED_PARTS_COST)
        - Each adjustment that a human makes must be accompanied with a note at granular level e.g., each new damage must have a note, if labor duration is changed then add the note on why it was adjusted
        - Human reviewer provides a final customer_note that tells what changes were made
        - Human reviewer provides a final internal_note that tells what changes were made - this will not be shown to customer

### Business Intelligence Dashboard (executives & insurance ops)
* this would require a separate table (that will represent a warehouse)

    - show raw data with NLP query interface, user can generate reports with rich graphs
        - A drop down box will have some common queries
        - "how many claims were processed in Q1 that required human feedback?"
        - "how many claim estimates needed adjustment during repairs?"
    - Business KPI dashboard
        - Efficiency
            - Auto-Adjudication Rate: The percentage of claims processed entirely by the system without manual intervention.
            - Claim Cycle Time: The average number of days from when the First Notice of Loss (FNOL) is received to when the claim is settled or closed.
            - First Contact Resolution (FCR) Rate: % of claims resolved within the first call or within 24 hours of FNOL.
            - Claims per Adjuster (Active Inventory): Number of open claims per full-time adjuster.
        - Accuracy
            - Claim Leakage: Financial loss due to preventable overpayments, missed subrogation opportunities, or duplicate payments.
            - Cost per Claim: The total operational cost (labor, technology, and admin) to process a single claim from start to finish.
            - Fraud-Detection Rate: The percentage of fraudulent claims accurately identified by the system relative to total claims processed.
        - Quality
            - Appeal/Dispute Rate: The percentage of automated decisions that are challenged by policyholders; a high rate may indicate issues with automation logic.
            - Overturn Rate: The frequency with which manual reviews override or reverse an initial automated decision.
            - Customer Satisfaction (CSAT/NPS): Scores derived from policyholder feedback that measure their experience with the speed and transparency of the adjudication process.
* KPI

    * For cost : saving will be a factor of 0.9 if customer accepted the AI generated estimate without appeal, 0.8 if customer appealed and accepted the revised human reviewed estimate
